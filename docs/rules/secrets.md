# Rule: API keys

PulseOps holds vendor API keys (healthchecks.io, Better Stack, GitHub, and later the collector's app tokens). This rule applies to all of them.

1. **Read keys only from the environment.** Use `readSecret(env, NAME)` from `src/secrets.ts`. Never read a key from a file in the repo, a command-line argument, or the database. A missing key fails with `E_CONFIG_MISSING` and exit code 2, naming the variable and never inventing a value. A key shorter than 16 characters, or with characters other than `A-Z a-z 0-9 . _ -`, fails with `E_CONFIG_INVALID`. Each other character is escaped by some common encoder (.NET JSON writes `+` as `\u002B`, some JSON writers write `/` as `\/`, `URLSearchParams` writes `~` as `%7E`), and an escaped key is a form redaction does not recognize.
2. **Never write a key to a log.** All output goes through the logger from `createLogger`. Its fields are `string | number | boolean` only: the type refuses objects and Errors, and a non-primitive value that gets past the type is written as `"[dropped: object]"`. An error becomes fields only through `formatError` (`src/format-error.ts`): its class, and for a PulseOps error its `E_*` code and our own message; for a vendor error also its status, the URL already redacted and the redirect kind, and for an unreachable vendor the cause's class and a network code from a fixed list (such as `ECONNREFUSED` or `TimeoutError`). It never writes a library's message, stack or cause text, or a vendor's response body, and it never throws: every read of the error goes through one guarded helper, so a read that throws loses only its own field. Our own messages never quote library text either: an argument error says only `invalid arguments`, and a `fleet.yaml` parse error gives only the line and the parser's code. A non-string message is dropped like a field. The whole line then passes through redaction as a second layer. Commands start through `runMain`, which logs uncaught errors the same way and then exits 1, even if a socket or timer is still open, and after 2 seconds even if stderr never drains (on Linux a full pipe blocks before that timer can run). Do not use `console.log` or `process.stdout` for anything that might hold a request, a response or an error. Vendor calls go through `getJson(url, headers, redact)`, which redacts the URL in every error and never keeps the response body. It never follows redirects: on a cross-origin redirect `fetch` drops only `Authorization`, so a header such as `X-Api-Key` would reach the new host. A 3xx fails as `E_VENDOR_HTTP` with a fixed `error_redirect` of `same-origin` or `cross-origin`; no `Location` text is ever kept, because a vendor could encode a key into it. A vendor base URL taken from the environment, such as `HEALTHCHECKS_API_URL` for a self-hosted healthchecks.io or a test server, must be https, or http only to `localhost`, `127.0.0.1` or `[::1]`, with no user or password in it. Anything else fails with `E_CONFIG_INVALID` before a key is sent.
3. **Never store a key in a database in plain text.** Build the exact text the row will hold, then call `assertNoSecrets(text, secrets, '<table> row')` on that string before writing it. It takes only a string, so what is checked is what is written. It throws `E_SECRET_IN_OUTPUT` instead of redacting, because a stored key cannot be taken back. App tokens are stored only as hashes, as the plan says.
4. **Never put a key in an LLM prompt.** Call `assertNoSecrets(prompt, secrets, 'LLM prompt')` on the final prompt string before sending it.

## What counts as the key

The raw value, its URL-encoded forms (`encodeURIComponent` and `URLSearchParams`, upper or lower case), the form with `/` written as `\/`, the JSON-escaped version of each, its base64 form, and any base64 value that decodes to text containing it, such as an HTTP Basic auth header, even when glued to a path or other text. Keys shorter than 16 characters are rejected, because redacting them could match ordinary text. `createRedactor` applies the same length and character rule to a `Secret` built by hand, so no path skips it.

## How it is tested

`test/no-leak.e2e.test.ts` starts a local server that rejects every request with 401 and echoes the key back in the body, the way some real APIs do. A real child process reads a random fake key from the environment, calls that server, and fails. The test checks the exit code, that the error code and the redacted URL are printed, and that no form of the key appears in stdout or stderr. A second fixture fails from a timer, from a rejected command, from a floating rejection and with a full stderr while a handle is still open, and the test checks that the process exits 1 with only the error's class logged. `test/log.test.ts` checks that only primitive fields are written and that a smuggled object is dropped; two `@ts-expect-error` lines make `tsc` fail if the field type ever widens. `test/format-error.test.ts` checks that a library error gives only its class.

## Not covered yet

- There is no database or LLM call in the code yet. `assertNoSecrets` is ready for both, and must be called on the final string at those boundaries when they are added.
- Redaction only knows keys passed to it. A key the process never read cannot be recognized.
- Errors thrown while a command module loads, before `runMain` starts, and Node's own warnings are not redacted.
- Response bodies have no size cap yet; only the 10-second timeout bounds them. They are read and dropped, never logged.
